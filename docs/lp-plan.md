# アジアンスター LP制作計画

作成日：2026-10-30

本書は企画時点の計画。2026-10-30の追加依頼によりサイト実装とヒーロー画像生成へ進行した。追加指示の「実装後の確認は自分で行うので不要」を優先し、本書の制作後の確認工程は実行していない。実装内容と編集箇所は `docs/EDITING.md` を参照。開発サーバー起動・公開は行っていない。

## 1. 目的と伝える順序

中野でタイ料理・インド料理を食べたい人が「何を食べられるか」「価格はどの程度か」「どこにあるか」を確認し、地図または電話へ進める1ページの日本語LPとする。

体験の順序は「料理に惹かれる → 人気料理を知る → タイ・インド料理の幅を知る → メニュー・価格を確かめる → 来店方法を確認する」。

主導線は「地図・アクセス」、補助導線は「電話する」。予約方法は未確認のため、電話リンクに予約確定を意味する文言を使わない。

依頼文末の「パンのおいしさ」は今回の店舗情報に合わせ「タイ・インド料理のおいしさ」と解釈する。

## 3. 素材調査結果

現在の素材場所は `src/assets`。依頼文中の `assets/menu` に当たるサブフォルダは現時点で存在しない。メニュー表も直下にある。

| 区分 | ファイル数 | 活用方針 |
| --- | ---: | --- |
| 料理写真 | 42 | すべての掲載を目標とし、人気料理・料理紹介・カテゴリ別メニューに割り当てる |
| メニュー表 | 17 | 価格と内容の照合元。重複・分割写真を整理してカテゴリ別に閲覧できるようにする |
| 店舗カード | 1 | 店舗名表記の参考。ポイント制度の現行条件が確認できるまで特典案内としては掲載しない |

店内・外観の実写は含まれていない。架空の店内写真は作らない。現状は料理写真と24席などの事実で店舗紹介を組み、店内写真が後から用意された場合に差し替えられる設計とする。

料理写真は約352〜800px幅。小さい写真を大画面全面に引き伸ばさず、皿の全体が見える構図を優先する。白背景、黒背景、テーブル背景が混在するため、写真ごとに背景色・余白・表示寸法を調整する。食材の色や盛り付けを変更しない。

### 完全重複が確認できたメニュー表

各組はSHA-256が一致する。同じ内容は1枚にまとめて掲載し、元ファイルは削除しない。

- `line_oa_chat_261027_153049.jpg` と `line_oa_chat_261027_153049 (1).jpg`
- `line_oa_chat_261027_153050.jpg` と `line_oa_chat_261027_153050 (1).jpg`
- `line_oa_chat_261027_153052.jpg` と `line_oa_chat_261027_153052 (1).jpg`

ほかにランチ表の全体・部分写真がある。読みやすい全体写真を主とし、必要に応じて部分写真を補助資料にする。

### 写真を料理名に割り当てる際のルール

単体写真とメニュー表を照合し、確実に一致する料理だけ名前を付ける。特にナシゴレンをガパオ、チョウミンや海鮮パッキーマオをパッタイ、トムヤムスープをトムヤムヌードルとして掲載しない。

実装時には42枚の素材一覧に「料理名・照合元・掲載場所・画像説明」を付けて管理する。名前が断定できない素材は照合を継続し、誤った料理名を付けて掲載しない。

## 4. デザインコンセプト

提案する方向は「香りのある食卓を、落ち着いたトーンで」。シックな背景と明るい料理写真を組み合わせ、入りやすさと料理の彩りを両立する。サイトとしての演出であり、実際の内装の表現とは区別する。

### 色と書体

| 用途 | 色の候補 |
| --- | --- |
| ヒーロー周辺・濃色帯 | 深いブラウン `#211B17` |
| メニューの明るい面 | 温かなアイボリー `#F4EEE4` |
| 罫線・小さな装飾 | 落ち着いた真鍮色 `#B89B68` |
| 導線・アクセント | 深い赤 `#8C3D2B` |
| 補助色 | ハーブを思わせる緑 `#4D5B42` |

見出しは細すぎない日本語明朝、説明と価格は読みやすいゴシック。本文はスマートフォンでも16px前後を目安とし、実装時にコントラストを確認する。

### 構図の方針

- ヒーローは全面写真に店名・短いコピーを重ねる。
- 主役の料理は大きく、補助の料理は小さく配置し、見せる順序を作る。
- 人気料理は5品を順に読める誌面風の構成。番号は掲載順であり順位の創作に使わない。
- メニュー一覧は検索性を優先して、整った列と価格の揃えで見せる。
- 装飾は細い罫線、余白、小さな星の意匠までに絞る。店舗ロゴの正式データがないため、ロゴ自体の再制作は前提にしない。

## 5. ヒーローの設計・生成画像のブリーフ

### レイアウト

PCは画面高の85〜100%程度、スマートフォンは75〜90svh程度を目安に調整する。食卓を全面に見せ、店名を中央寄り、短いコピーをその近くに置く。料理の主役部分には文字を重ねない。

ヒーローに載せる情報は以下に限定する。

- アジアンスター／ASIAN STAR
- コピー案「香りに誘われて、中野。」
- 補足「THAI & INDIAN CUISINE」
- 下端に「中野駅 徒歩1分」と「メニューを見る」への小さな導線

営業時間、電話番号、支払い方法などは直後の情報帯へ移す。ナビゲーションは料理・メニュー・店舗情報・アクセスの4項目程度に絞る。

### 生成する画像

制作着手後に、提供料理写真の皿・盛り付け・色味を参考にして生成する。暗めの木の食卓に、タイ料理とインド料理の両方が自然に並ぶ場面。例えばハーブの緑、カレーの赤〜オレンジ、ナンの焼き色が見える構成とする。

構図は斜め俯瞰。温かい照明、自然な影、料理が読み取れる露出とし、画像全体を暗くしすぎない。文字を置ける空間を中央上部付近に確保し、スマートフォンでも主役の料理が残るように組む。PC横長・スマートフォン縦長の2構図を用意する計画。

生成画像に文字、ロゴ、実在するように見せる内装、人物は含めない。ヒーローはイメージビジュアルで、実店舗や実提供料理の記録写真として説明しない。ページ内に「メインビジュアルはイメージです」と控えめに記す。個別メニュー紹介には提供素材を使う。

ヒーローは静止画1枚を基準とし、スライドショーは計画しない。

## 6. ページ全体の構成

### 01. ヒーロー

全面の生成画像と短いコピーで、料理ジャンルと店名を伝える。

### 02. 来店の基本情報帯

「中野駅から徒歩1分」「11:00〜23:00」「年中無休」を横並びの細い帯にする。スマートフォンでは折り返し、文字を縮めない。

### 03. 人気の5品

「まず味わいたい、5つの料理。」を見出し案とする。ガパオライス、パッタイ、カオマンガイ、トムヤムクンヌードル、カレーをユーザー指定順で紹介する。

PCでは大きな写真1点と小さな写真・説明2点を上下のまとまりに分け、次のまとまりで写真位置と余白を変える。読み順は常に料理名・写真・短い説明・価格とする。料理名・価格は画像内に焼き込まずHTMLで表示する。

スマートフォンは1品ずつ縦に並べ、品名、写真、1〜2文の説明、価格を順に置く。大きさの変化は保ちつつ、左右の大きな位置ずらしを避ける。

カオマンガイは `line_oa_chat_261027_153022.jpg`、カレーは `line_oa_chat_261027_152945.jpg`、`line_oa_chat_261027_152947.jpg` 等をメニュー表と照合して使う。

ガパオ・パッタイ・トムヤムクンヌードルは、現状の42枚から対応する単体写真を確定できていない。`line_oa_chat_261027_153100.jpg` または `line_oa_chat_261027_153043.jpg` 内の該当写真を切り出す案を検討する。ただし切り出せる画素数が少ないため、小さな補助画像の範囲にとどめる。実寸で画質が足りない場合は、元のメニュー表を拡大閲覧できる導線と料理名・説明で紹介し、単体写真の追加後に大きく見せる設計とする。5品すべてを同じ大きさの写真で見せられるとは現時点で確約しない。

### 04. タイ料理の章

タイ料理の麺・ごはん・カレーと、サラダ・前菜などの多様性を写真の大小で伝える。横長の料理紹介の下に正方形写真を数点配置し、説明文は各料理の特徴に絞る。

カオマンガイ、グリーンカレー、レッドカレー、生春巻きなど、照合できた料理写真を中心にする。おすすめ5品で使った写真の繰り返しは必要な範囲に抑える。

### 05. インド料理の章

白背景のセット写真を温かなアイボリー面に配置し、その下にカレーとナンを別々に並べる。タイ料理の章とは構図と背景を変える。

セット4枚、カレー5枚、ナン4枚、タンドリー料理等を、料理紹介と次の一覧に割り当てる。素材に見えるチーズや焼き色は写真で見せ、未確認の調理工程や仕入れの説明は書かない。

### 06. メニュー・料理写真一覧

人気料理と各料理紹介で使ったものを含め、料理写真42枚すべてに掲載場所を割り当てる。本文で大きく使わない写真はカテゴリ別の一覧へ配置する。1画面で42枚を読み込まず、下部の画像は遅延読み込みする。

カテゴリ案は「タイのごはん・麺・スープ」「タイカレー」「インドカレー」「ナン・セット」「肉料理・グリル」「前菜・揚げ物・サラダ」。実際の料理名とメニュー表を照合して最終分類する。

PCは料理写真の比率に合わせ2〜4列、スマートフォンは小さな写真を2列、説明が必要な料理を1列で表示する。料理名と価格が先に探せる一覧にし、すべてを装飾カードで囲わない。

同じ場所に「ランチ」「ディナー」「単品」のメニュー表をまとめる。表紙のサムネイルから選び、正しい向きで開く拡大ビューを用意する。Escで閉じる、閉じた後に元のボタンへフォーカスを戻す、キーボードでも操作できる設計とする。元画像を開くリンクも付ける。画像の拡大によって元の解像度以上の文字が読めるとは扱わず、主な料理・価格・区分はテキストでも用意する。

### 07. お店について・利用シーン

「中野で、タイとインドの料理を。」を見出し案とし、24席、一人での食事や一杯、家族との食事、仕事での食事という利用のきっかけを短い文章で紹介する。実写の内装がないため、料理のある食卓の写真構成と店舗情報を使い、席の様子は推測して書かない。

### 08. アクセス・店舗情報

住所、電話、営業時間、定休日、席数、支払い方法をまとめる。PCは読みやすい表と地図を組み合わせ、スマートフォンは店舗情報→地図→大きな「地図を開く」ボタンの順。

所在地を確認したうえで地図リンクを設定する。出口名、ビルへの入り方、駐車情報は追加確認なしに補わない。地図埋め込みを採用する場合も遅延読み込みと外部地図リンクを用意する。

フッターに店名と電話・地図導線を置く。スマートフォンはヒーローを過ぎた位置から下部に「メニュー」「地図」「電話」の固定導線を出す。下部余白を確保し、本文を隠さない。

## 7. メニュー価格の扱い

以下は提供メニュー画像からの読み取り値であり、現行価格・税込表記の確定値ではない。

| 料理 | 単品表での読み取り | 別区分の記載 |
| --- | --- | --- |
| ガパオライス（表記：カオパッガパオ） | 950円 | ランチ表・ディナーセット表にも950円の記載 |
| パッタイ | 890円 | ランチ表900円、ディナーセット表890円 |
| カオマンガイ | 950円 | ランチ表990円、ディナーセット表950円 |
| トムヤムクンヌードル（単品表：トムヤムクンラーメン） | 890円 | ランチ表950円、ディナーセット表890円 |
| カレー例：チキン／バターチキン | 850円／900円 | カレー種類・セット区分で異なる |

パッタイ、カオマンガイ、トムヤムクンヌードルについて、ランチとほかの区分を混同しない。単品・セットで内容が異なるため、同じ価格でも同じ商品としてまとめない。

メニュー表にはランチ11:00〜17:00、ディナー17:00〜23:30と読める記載がある。営業時間はユーザー指定の11:00〜23:00を優先する。ランチの提供時間、ディナーセットの現行内容、税込・税別は実装時に確認できるまで確定表示しない。メニュー原本内にも営業時間の相違があるため、公開時には原本の扱いを整理する。

## 8. GSAP・Lenisのアニメーション計画

現在の `package.json` にAstro、GSAP、Lenisが含まれていることを確認済み。今回は追加・更新しない。

| 対象 | 演出案 | 目安 |
| --- | --- | --- |
| ヒーロー | 画像をすぐ表示し、店名とコピーを短くフェード表示 | 0.7〜1.0秒 |
| ヒーロー画像 | 必要ならごく小さな縮小を1回だけ | 1.03→1.00程度 |
| 料理紹介 | 画面に入った写真と説明を順に表示 | 0.5〜0.7秒、移動12〜20px |
| 章の見出し | 見出しと罫線を穏やかに表示 | 0.4〜0.6秒 |
| PCの写真 | 大きな写真の一部だけスクロールに合わせて微移動 | 12〜24px程度 |
| ボタン・メニュー | 色・下線・開閉の自然な変化 | 0.15〜0.25秒 |

GSAPとScrollTriggerを表示タイミングや微小な移動に使い、Lenisは主にPCのホイールスクロールを穏やかに整える。連携は公式ガイドに従い、GSAP側の更新に同期させ、二重のアニメーションループを作らない。

スマートフォンはネイティブのタッチ操作を優先し、画像のパララックスを省く。画面を長く固定する演出、強制的な横スクロール、常時流れる料理写真、文字の1文字ずつの長い表示は計画しない。

`prefers-reduced-motion` では移動・拡大・慣性スクロールを停止して即時表示する。JavaScriptが失敗しても料理名・写真・価格・電話・地図を閲覧できる初期状態にする。メニュー表の拡大ビュー中は背景のスクロールを止め、閉じた後に復元する。

## 9. 実装時の品質目標

- Astroの静的なHTMLを軸に、必要な操作だけJavaScriptを使う。
- 画像は幅・高さを指定し、表示サイズに合う変換画像を生成する。元画像の解像度を超える強引な拡大を避ける。
- ヒーロー画像を優先し、下部の料理写真と地図を遅延読み込みする。
- モバイルで固定導線が本文やブラウザ操作を邪魔しないことを確認する。
- フォントや暗色背景で細い文字が読みにくくならないようにする。
- 料理一覧とメニュー表にキーボードで到達できるようにする。
- 店名、中野駅、タイ料理、インド料理を自然な日本語のタイトル・説明文に含める。
- 公開URL確定後にcanonical・OGP・サイトマップ・robotsを設計する。
- Restaurant構造化データは確定済み店舗情報のみ。生成ヒーローを実店舗写真として登録せず、評価や口コミを作らない。
- ビルド、写真と料理名の照合、価格区分、スマートフォン表示、リンク・拡大ビュー、動きを減らす設定を制作後に確認する。

## 10. 制作に進む際の順序

1. 本計画に基づき、42枚の料理名・掲載場所、メニュー表の現行価格・税区分を整理する。
2. 人気5品の写真対応と低解像度写真の表示可能寸法を確定する。
3. 生成ヒーローのPC・スマートフォン用画像を制作し、料理と文字の位置を調整する。
4. ページのレイアウト、メニュー閲覧、来店導線を実装する。
5. GSAP・Lenisの演出を追加する。
6. 表示・内容・リンク・動作を確認する。

現時点で回答を待たずに計画できる範囲は本書に記載済み。価格の税区分、メニュー表の営業時間相違、人気3品の単体写真不足、店内写真不在は、制作時に表示内容を決めるための確認事項として残す。
